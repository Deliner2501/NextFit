# Data dictionary

All the tables of the Oracle database, with the meaning, type and rules of each column.
See the [entity-relationship model](er-model.md) for the diagram.

**Key:** `PK` primary key, `FK` foreign key, `UK` unique. **Null:** `No` means the column is required.
Names of Java constants (`Role`, `PaymentMethod`, `MuscleGroup`, `Difficulty`, `AssignmentStatus`,
`AuditAction`) are stored by name.

## `users`

People who sign in to NextFit (administrator, reception, trainer).

| Column | Type | Null | Key | Description |
|---|---|---|---|---|
| `id` | NUMBER(19) | No | PK | Identifier. Generated by the database (identity column that also accepts a given value, for the CSV migration). |
| `username` | VARCHAR2(60) | No | UK | Name used to sign in. Unique. |
| `full_name` | VARCHAR2(120) | No |  | Full name. |
| `password_hash` | VARCHAR2(200) | No |  | Salted hash of the password. The password itself is never stored. |
| `role` | VARCHAR2(30) | No |  | Name of the `Role` constant (decides which screens the user can open). |
| `active` | NUMBER(1) | No |  | 1 = the user is active, 0 = deactivated. Default 1. |

## `payments`

Money received for a subscription.

| Column | Type | Null | Key | Description |
|---|---|---|---|---|
| `id` | NUMBER(19) | No | PK | Identifier. Generated by the database (identity column that also accepts a given value, for the CSV migration). |
| `subscription_id` | NUMBER(19) | No | FK | Subscription that is paid. References `subscriptions(id)`. |
| `member_id` | NUMBER(19) | No | FK | Member who paid. References `members(id)`. |
| `paid_at` | TIMESTAMP | No |  | Moment of the payment. |
| `method` | VARCHAR2(30) | No |  | Name of the `PaymentMethod` constant (cash, card...). |
| `subtotal` | NUMBER(12,2) | No |  | Price before the discount, in pesos. |
| `discount_type` | VARCHAR2(30) | Yes |  | Kind of discount: `NONE`, `PERCENT` or `FIXED`. |
| `discount_value` | NUMBER(12,2) | Yes |  | Number of the discount: a percentage for `PERCENT`, pesos for `FIXED`, 0 for `NONE`. |
| `registered_by` | VARCHAR2(60) | Yes |  | User name of the person who registered the payment. |

> The total is not stored: it is calculated from `subtotal` and the discount, so it can never disagree with them.

## `routine_lines`

One row per exercise of each day of a routine.

| Column | Type | Null | Key | Description |
|---|---|---|---|---|
| `routine_id` | NUMBER(19) | No | PK, FK | Routine. References `routines(id)`. |
| `day_index` | NUMBER(3) | No | PK | Number of the day inside the routine (0, 1, 2...). |
| `line_no` | NUMBER(5) | No | PK | Position of the exercise inside the day: it keeps the order. |
| `day_name` | VARCHAR2(60) | Yes |  | Name of the day, for example "Monday - Chest". |
| `exercise_id` | NUMBER(19) | No | FK | Exercise to do. References `exercises(id)`. |
| `sets` | NUMBER(4) | Yes |  | Number of sets. |
| `repetitions` | NUMBER(4) | Yes |  | Repetitions per set. |
| `rest_seconds` | NUMBER(5) | Yes |  | Rest between sets, in seconds. |

> The key has three columns: a routine can repeat the same exercise in a day, so only the position tells the lines apart.

> A day without exercises has no rows, the same as in the CSV files.

## `audit_log`

Record of what the users did (sign in, create, edit...). Rows are only added.

| Column | Type | Null | Key | Description |
|---|---|---|---|---|
| `id` | NUMBER(19) | No | PK | Identifier. Generated by the database (identity column that also accepts a given value, for the CSV migration). |
| `event_time` | TIMESTAMP | No |  | Moment of the event. |
| `username` | VARCHAR2(60) | Yes |  | User name of who did it. Text, not a foreign key: the record stays even if the user is deleted. |
| `action` | VARCHAR2(40) | No |  | Name of the `AuditAction` constant. |
| `detail` | VARCHAR2(1000) | Yes |  | Extra information about the event. |

> It is called `audit_log` and not `audit` because AUDIT is a reserved word in Oracle.

## `face_templates`

Numeric description of a face, used by the face access. Never a photo.

| Column | Type | Null | Key | Description |
|---|---|---|---|---|
| `id` | NUMBER(19) | No | PK | Identifier. Generated by the database (identity column that also accepts a given value, for the CSV migration). |
| `member_id` | NUMBER(19) | No | FK | Member the face belongs to. References `members(id)`, `ON DELETE CASCADE`. |
| `embedding` | VARCHAR2(4000) | No |  | The 128 numbers of the face vector, separated by semicolons (about 1.4 KB). |
| `created_at` | TIMESTAMP | No |  | When it was stored. Default: now. |

> A member can have several rows (several samples of the same face).

## `access_settings`

One row holds the carnet signing key shared by all NextFit installations using this database.

| Column | Type | Null | Key | Description |
|---|---|---|---|---|
| `id` | NUMBER(1) | No | PK | Always 1, enforced by a check constraint. |
| `access_key` | BLOB | No | | The signing key. Each installation caches it in its local `access.key` file. |
